# 毁灭者血条实验

## 当前范围

最终目标是全部 Boss；当前仅给普通／神圣毁灭者头部设置 `DestroyerBossBar`，文件位于 `Basic/Graphics/BossBars`。其他 Boss 沿用原状。使用默认 Boss 血条样式时，官方调度调用本条 `PreDraw`，自绘后返回 false，不再画默认框、头像或生命数字。

灾厄／Infernum 等独立 `ModBossBarStyle` 可以绕过这个入口；本实验不强制切换玩家样式，不宣称适配那些独立绘制器。

## 显示

- 屏幕底部居中，宽度为屏幕逻辑宽度 56%，最多 920；外框高 11，红色填充高 7，底部距离 90。尺寸集中在 `DestroyerBossBar` 常量中。
- 名称和称号使用 `Mods.AdvancedMod.BossBars.Destroyer` 已有本地化；根据实例 Hallow 标记选择普通或神圣称号。
- 红条读官方绘制参数的当前／最大生命；黄条在受伤后保留 24 更新刻，再每刻减少最大生命比例 0.012，直到追上红条。治疗立即提升两条；视觉状态按毁灭者实例保存，不在共享 ModBossBar 中保存。
- 右下显示探测怪图标、环形剩余比例和当前／最大计数。实验采用原版探测怪首帧；`DrawBar` 参数可替换贴图、源矩形、当前值和上限。上限非正时隐藏圆环。
- 环形指示和细条使用 SpriteBatch 与明确 1×1 源矩形，无新增 Shader 或纹理文件。贴图的完整尺寸不能当作单像素使用。

## 探测怪规则与网络

`DestroyerBarState` 只实例化于毁灭者头部和探测怪。头部在链生成后统计实际身体数量，固定为初始上限；初始已附着并有来源关联的探测怪亦计入。尾部不携带可释放探测怪，不计入。

原版身体 `HitEffect` 用父实体出生来源生成探测怪；在 `OnSpawn` 记录所属头部槽位及战斗编号。释放不改变剩余数。服务端／单人 `OnKill` 仅向仍匹配战斗编号的头部记一次击败，再设置头部 `netUpdate`。剩余数为初始上限减击败数，因此自然失活不等于击败，也不会被扣除。

初始上限与击败数通过 ExtraAI 同步，客户端不自行扫描探测怪来猜剩余值。晚加入同样获取该账本；原版生命同步继续复用。红黄条插值属于客户端表现，不发送每帧视觉状态。

当前没有为任意第三方自定义探测怪生成方式补猜归属；没有正确父来源的额外探测怪不纳入账本。

## 实验验证

测试环境变量 `ADVANCEDMOD_BOSSBAR_TEST` 仅由隔离测试脚本设置，正常游戏不启用测试驱动。

```powershell
pwsh -File Tests/Run-BossBarLive.ps1 -Mode preview
pwsh -File Tests/Run-BossBarLive.ps1 -Mode live
pwsh -File Tests/Run-BossBarNetwork.ps1
```

脚本依赖已有 `obj/element-live` 的隔离玩家、世界及依赖模组。预览使用固定样例；正式实例与网络测试让原版生成链，然后冻结运动以便观测血条，真实调用 HitEffect 释放探测怪并调用伤害入口击败。半血阶段为定向设置权威生命以验证同步；单人另通过身体真实受击检查共享生命。

网络脚本启动服务端与两个客户端，第二客户端在首次同步完成后加入；随后服务端释放十只、击败五只、同步半血。数值报告与实际截图分别验收，不以截图文件存在代替视觉检查。
