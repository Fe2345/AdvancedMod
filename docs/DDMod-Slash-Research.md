## 建议的程序化重建

以下为新实现建议，不是 DDMod 着色器原公式。将几何轮廓与表面纹理分开：几何控制半径、弧角、尾端收尖和宽度；纹理只控制弧内的亮暗细节。这样无需为每个弧角生成一张月牙 PNG。

### 条带纹理与颜色

定义 u=尾到头的归一化弧长，v=内缘到外缘的归一化宽度。与 DDMod 的历史索引方向不同，接入时明确翻转，不假设同向。

- 主体遮罩：M(u,v)=E(u)×B(v)，E 控制尾部渐隐，B 控制内缘柔化、外缘清晰；端部使用平滑过渡避免矩形截断。
- 平行细条纹：L(u,v)=Σ a_i exp(-((v-b_i(u))/s_i)^2)。b_i 为各条亮线的位置，s_i 为宽度。让亮线在 v 上分布、沿 u 延伸，贴到弧形网格后自然成为平行弧线。
- 微扰：b_i(u)=b_i0+ε_i N(k_i u+φ_i)，ε 保持较小；噪声主要调制亮度，避免把清楚的外轮廓抖成火焰。
- 材质强度：I=M×(c0+c1 L)×(1+η N2(u,v))。N2 可用固定种子的低频值噪声叠加实现；这是替代 Wave 的近似材料，并非原图的逐像素复原。
- 建议沿 u 使用青蓝→青绿→亮绿渐变，与截图尾部青蓝、头部亮绿对应；保留少量偏白的高亮细线，避免全带饱和白。渐变方向须以动态预览验证。

优先一次性生成可缓存的灰度条带纹理（例如 256×64 作为试验起点，尺寸与条纹数集中配置），用顶点色或效果参数着色。纹理在图形线程创建，专服不创建，卸载释放；不在每帧 SetData。需要流动时平移可平铺噪声的采样坐标，主体端点遮罩保持固定，避免整个尾端也随材质滚动。

### 轮廓与星光

- 若目标是保留当前天裁的明确轮廓：继续使用三层相切圆边界，保持 64 像素／135°约束，为每层补充 UV 和细纹理。它会是参考 DDMod 材质的天裁效果，不能称为 DDMod 原样复现。
- 若目标是复现 DDMod 的运动拖尾：使用历史刀刃采样构建条带，宽度和可见弧长随轨迹演化；不能仅替换当前贴图就得到相同动态。是否调整现有几何需另行确认。
- 星光独立生成：两个窄长高斯光瓣加中心光晕，例如 H(x,y)=exp(-(x/a)^2-(y/b)^2)+exp(-(x/b)^2-(y/a)^2)，a≪b。用单独的粒子／绘制命令控制位置、寿命与闪烁，不烘焙进弧面。
- 主体采用预乘 Alpha，辉光独立采用现有 One/One；生成纹理时同步预乘 RGB 与 Alpha，避免透明边缘黑边或重复乘 Alpha。不同通道可在一张纹理内编码，但第一版不必引入通用材质框架。

## AdvancedMod 接入边界

已现场核对当前文件：

- Basic/Graphics/Rendering/VfxTextures.cs 已有按需生成、缓存及卸载模式，可沿用生命周期。
- VfxMesh.cs 使用 VertexPositionColor，没有 UV。LayeredTangentCrescent 是三层几何亮带，不是纹理采样。
- VfxDrawQueue.cs 显式关闭 BasicEffect.TextureEnabled，现有队列不能仅靠添加一个 Texture2D 就绘制纹理。
- 真正接入需要带 UV 的顶点数据、纹理绑定和对应绘制分支；应先针对剑气做最小改动。新增可复用设施须与作者核对，避免顺手重构整套 VFX。

建议验证顺序：先看黑底／灰底的静态轮廓、条纹和透明边缘，再看连续挥动的尾部衰减、UV 朝向、攻速变化与星光密度，最后做游戏内遮挡、缩放及生命周期验证。
