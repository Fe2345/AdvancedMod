# 元素 Prepare／Reaction 框架

## 当前边界

2026-10-23：`Basic/Element` 已实现可离线运行的两层框架、目标状态和串行结算外壳。NPC 的 `CombatGlobalNPC.Elements`、玩家的 `CombatPlayer.Elements` 分别持有独立目标；NPC 设置默认值、玩家初始化时创建新目标。

单人四条正常伤害入口与每刻静置驱动已接入，并已在真实客户端验证；完整使用方式、入口边界及测试脚本见 [Element-Usage.md](Element-Usage.md)。联机执行端、同步及去重仍待实现。原 Word／转写 Markdown 继续作为原稿留存，以 TODO 和本文件描述当前实现。

## 数据流

1. 上游读取直接攻击实体的面板与两个修正，构造不可变 `ElementRequest`。复用既有 `HitSnapshot`、`TagSet`、`SourceInfo`，不重新定义伤害上下文。两个修正在创建请求时冻结，没有武器到弹幕的继承。
2. `ElementTarget.Submit` 将尚未解析的请求入队。目标忙碌时立即返回；取得执行权后才执行 Prepare。
3. Prepare 复制已提交状态，按四路线分流。正元素量先进入工作副本，再按反应槽编号递增检查 CD 和足量消耗。高编号没有独立优先级函数；登记顺序不影响选择。
4. Reaction 在工作副本上规划消耗、白值、CD 和最终标签，输出 `ReactionPlan`。公开计划只读，目标公开快照仍是旧状态。主动按白值从低到高取量，静置反向；同白值合并，允许部分消耗。
5. 外壳调用 `applyDamage(plan)`。宿主用最终 `plan.Hit` 构建 Calculate 输入，再使用 `DamageSeed` 应用伤害。系数已经包含在种子内，不能重复提交到反应增伤乘区；自定义反应增伤仍由 Calculate 正常处理。
6. 回调返回 true 才提交元素和 CD，然后产生真实 `ReactionOutcome` 与独立表现请求。false 表示不提交。已确认的原生适配条件为正常返回且实际正伤害；取消／免疫／闪避／零伤害不提交，致死仍记录反应结果，实体身份变化禁止旧状态写入。
7. 完成回调之后才处理下一请求，重新读取最新状态。伤害回调或完成回调内再次 Submit 只入队，不递归解析。

异常会清空未处理队列、释放执行标志并向上传播，保留最后一次已提交状态；已经调用引擎造成的伤害无法回滚。宿主可传 `isTargetValid`，出队前和提交前都会检查；宿主负责将实体代次／身份纳入检查，不能只判断索引有效。

## 状态与数值约定

- 元素 10 槽，每槽保存整数面板白值到 double 元素量的字典及缓存总量。读取返回独立只读快照；统一通过目标队列附着，不公开可写数组。
- CD 为 float 的 20 槽数组，容量复用 Calculate 常量；同目标同反应共享。
- 反应表固定 20 槽，按槽号扫描。当前标签映射为水雷 1、水风 2、火冰 3；元素槽沿用标签注释 1–6，预留槽不自动赋予标签语义。
- 首版仅接受正元素量对应唯一元素标签；多元素申请尚未定义，明确报错。零元素量可以携带已有计算标签。主动请求只匹配包含来袭元素的候选；静置扫描所有候选。
- 正元素量在工作副本中累加，不足以支付修正后消耗的候选被跳过，不做部分反应或缩放。每次请求最多选择一个反应。
- 当前数值效果：将所有实际消耗分量按元素量加权求面板平均值，再乘反应系数得到 `DamageSeed`。没有再次叠加职业增伤。正式复杂反应、异化和派生产物仍待定义。
- 实现入口拒绝负值、非有限值及零消耗修正；CD 修正允许 0，基础 CD 允许 0。消耗乘积下溢到 0 或溢出时报告错误。该合法域是当前框架防御性校验，不代表负修正玩法已经确认。
- 耗尽分量删除，保留非零余量；总量按分量重新求和并缓存，不使用绝对 epsilon 删除合法微量元素。正式衰减、覆盖及浮点容差策略仍待确认。

## 游戏刻入口

宿主每个游戏刻调用 `Tick(gameTick, idleRequest, table, applyDamage, completed, isTargetValid)`。静置请求使用 `isIdle: true`，无来袭元素量，两个修正固定为 1；框架将伤害来源设置为环境并清除攻击者。

当前可测试调度约定：先递减 CD，再做一次静置候选选择；同刻重复 Tick 不重复递减或扫描，跳过的游戏刻按差值递减。Tick 自身也进入同目标队列，主动请求与 Tick 按调用先后串行执行。首次 Tick 递减一刻；未匹配反应时不调用伤害回调。现由单人 PostUpdateEverything 驱动；跳过死亡玩家和无状态目标。玩家入世界／重生重新创建目标状态。正式每刻反应次数及联机行为仍待确认。

框架仅用于主线程；队列不是跨线程或跨端互斥设施。`DefaultOperationLimit=1024` 为防止无限派生链的工程保护上限，可通过构造参数覆盖；超限显式报错，不静默丢弃后继续结算。
