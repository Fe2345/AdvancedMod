# 毁灭者二阶段运动与充能验收（2026-10-30）

> 本文保留早期运动阶段证据；当前五类弹幕、魔焰拖尾和Ultimate预览见[弹幕专项验收](../destroyer-attacks/README.md)。

## 本轮范围

保留一阶段运动、探测怪释放和弹幕行为。魔焰缺少拖尾、旋风反射／返程生硬、未释放数量低于40时概率自行脱离三项仅记录在 TODO，未实施。

探测怪账本初始化后归零，神圣毁灭者自动进入 Prepare，随后按 Reposition→Telegraph→Crash→Recover 执行两次冲撞，再进入 Idle。二阶段身体关闭激光，继续原链跟随与旋转；原灯圈重新显示对应元素色。白天／失去目标仍走原撤退逻辑，撤退也不恢复身体激光。

参数集中在 DestroyerPhaseTwoRules：巡航14、冲撞21，30刻 SmoothStep 提速、42刻减速、150刻 Idle。预警至少30刻，正式发动同时检查900—1200像素距离和15度夹角；太近先整理位置。发动时预测玩家12刻位移并限幅128，之后以每刻至多0.5度对齐锁定方向，不持续追踪玩家。越过锁定点500像素结束，最长120刻兜底。

这些是运动试验初值。实际玩家控制手感、身体封路和加入技能弹幕后是否公平尚未收敛，不能由脚本通过推断为平衡完成。

## 反应与 Ultimate

DestroyerReactionCounter 监听 ElementHitSystem.Resolved，只接受成功提交且 IsHallowed、目标为玩家、攻击来源归属于当前毁灭者实例的反应。NPC接触附加神圣资格但不附加元素；目前的来源组件只匹配已有 DeathLaser／PinkLaser 类型，后续新增技能弹幕需显式扩展类型匹配及来源继承。玩家打在Boss身上的反应、普通反应、仅附着和取消命中均不充能。

使用头部槽位＋战斗 Encounter 区分实例，客户端反应回执另有256项去重窗口，允许事务完成顺序与 HitId 顺序不同，连接与世界清理时重置。玩家受伤仍由所属客户端结算；131号消息报告反应，服务器验证活跃玩家、Boss与战斗身份后维护计数并同步。该机制沿用现有玩家受伤的客户端权威，不声称服务端重新模拟了整次反应。

充能封顶20；每次进入 Idle 抽连续阈值 r∈[0,20)，r<次数则释放。满20时当前技能结束后必放，不在冲撞中途打断。释放清零，Ultimate 先采用作者确认的流程版：整条链隐藏且不能接触伤害玩家或友方NPC，三轮45刻预警状态与18刻鞭打状态后恢复循环。不生成正式鞭形、预警线或伤害。二阶段五种技能弹幕也未生成，因此本轮反应流程通过隔离测试攻击验证。

血条一阶段仍显示探测怪数量；二阶段显示反应次数／20与预载的 Assets/UI/HallowIcon。

## 证据

- 构建：0警告、0错误。既有 unknown image type 打包提示未阻止加载。
- [客户端专项报告](singleplayer.json)：35/35。使用真实NPC链，原生 HitEffect 释放并击败全部探测怪，自动进入二阶段；在客户端中直接逐刻调用正式 AI 并更新位置以加速多场景运动验证，不将其称作完整人工战斗。
- 静止玩家两轮循环共4次冲撞，起点约1130—1185像素；运动阶段最大单刻速度变化约0.65。7像素／刻匀速、7像素往返、10像素横移叠加上下运动三种目标均完成双冲，分别使用579、850、874刻。
- 计数通过实际 Projectile.Damage→玩家受伤→元素事务结算，验证20次满充、封顶、技能结束必放、清零和后续重新累计；另覆盖普通／其他来源／失效Encounter／免疫／仅附着过滤、回执去重与重连清理。
- 三次 Ultimate 状态、全链隐藏及禁止接触伤害、恢复循环和白天仍无身体激光均通过。实际世界截图见 [phase2-world.png](phase2-world.png)，另通过同一正式血条绘制函数导出上方清晰样本。
- 最终真实TCP三端35/35：[服务器11项](network-server.json)、[召唤客户端13项](network-client1.json)、[晚加入客户端11项](network-client2.json)。运行目录为 obj/mechanical-network/20261030-195706，日志未检出Exception／ERROR／underflow，三端均为一次Ultimate完成后7点充能。夹具在服务器生成带已确认来源的测试元素弹幕，玩家客户端收到后显式调用一次原生Projectile.Damage，实际受伤并回报，完成后销毁样本。充能期间固定同一次Crash直到满20，隔离NPC接触伤害；放行收招完成一次Ultimate后再累计7次，为晚加入验证固定最后展示窗口。没有直接修改正式反应计数，也不把该夹具称作自然碰撞手感测试。
- [原版状态机回归](vanilla-regression.json)：最终代码52/52，确认普通／神圣分流、一阶段运动对照、激光、链、原生释放和字段复用。

联机夹具修正记录：早期直接期望7次，但DeathLaser原生穿透3次，服务器临时修改penetrate并不会通过原版包覆盖客户端默认值，导致同一测试弹可多次真实反应。尝试命中端首次命中销毁后，受玩家更新时机／冷却影响，样本命中不稳定；最终改为与单人专项一致的显式原生Damage调用后销毁。另发现真实Idle抽签会在未满20时合法提前释放，因此固定同一次Crash收集20次，并隔离NPC接触伤害。上述只调整测试条件，没有把正式计数器改成忽略合法反应。
