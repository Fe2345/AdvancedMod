# 元素文字（2026-10-26）

元素伤害沿用原版 `CombatText` 的字体、数值和暴击强调，只替换颜色：火深红、水蓝、雷紫、冰浅蓝、叶绿绿色、风青绿。色值集中在 `ElementTextStyle.Rgb`。

反应名称读取 `Mods.AdvancedMod.Reactions`：导电、汽化、融化。显示中心位于目标左侧，文字右缘与目标保留 12 像素基础间距；每次随机倾斜 -10°～10°，固定世界位置停留 150 游戏刻（正常 60 Hz 下 2.5 秒），不随目标移动。以现存反应文字中心为圆心，32 世界像素内禁止生成新反应文字，恰好 32 像素允许。排斥跨目标、跨反应类型，但不限制普通伤害数字；原版文字池满时沿用其不生成行为。

颜色按作者确认的规则选择：优先取本次最终伤害标签中的首个基础元素；静置反应缺少攻击元素标签时，导电／汽化／融化分别取雷／水／火。因此冰伤触发的融化文字仍是冰色，导电派生链伤是雷色。标签重命名为 `PyroCryo`，序号和反应槽保持不变。

## 接入

旧诊断 JSONL 若以字符串保存了旧拼写 `PytoCryo`，重放前需将该标签字段迁移为 `PyroCryo`；网络与元素状态使用整数标签，不受此字符串更名影响。

现有托管近战、弹幕、玩家受伤、静置反应和导电链已接入，无须在饰品或武器中手动创建文字。新增正常元素武器仍使用 `ElementAttacks` 配置；第三方绕过托管事务直接 `StrikeNPC` 的调用不会凭空获得元素语义。

`ElementTextSystem.Prepare/PrepareNpc` 保存本击实体位置和方案，只有 `ElementHitSystem.Resolved` 的成功提交才生成反应名。取消、免疫、失败事务不展示。NPC 原生数值在 ToHitInfo 阶段记录，沿用原版显示的伤害值（包括过量伤害），不重新计算；先标记 `HideCombatText`，由原版命中包同步禁止重复数字，再发送一次元素展示消息。不会修改生命、防御或伤害公式。

玩家受伤通过 `Hurt(HurtInfo, bool)` 的嵌套安全作用域着色原生数字，只处理对应玩家位置上的受伤数字，不修改治疗文字。反应文字在成功后生成；冷却和附着不由表现模块更改。

## 联机与边界

- NPC 数字和反应名由服务器发送，客户端负责本地随机角度、32 像素排斥和寿命；没有每刻动画包。
- 玩家反应名沿用现有所属客户端结算方式，由服务器校验归属、标签和位置后转发，忽略原发送端以免重复。此协议沿用项目对所属客户端的信任，不是新增防作弊机制。
- 远端玩家的原生受伤数字只能从原版伤害来源恢复元素；没有可恢复来源的远端静置玩家伤害数字仍保留原版色，其反应名会按同步的元素着色。所属玩家本地的静置伤害数字使用完整方案选色。
- 原版伤害数字池和反应文字共用容量；游戏暂停时随原版更新一起暂停。退出世界、卸载或文字槽复用时清理对应状态。
- 本机按 tML 2026.08.3.0 的实际 `CombatText.Update`、`NPC.StrikeNPC` 和 `NetMessage.SendStrikeNPC` 方法核对；不覆盖其他模组完全替换上述绘制／命中流程的情况。
